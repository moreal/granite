# 로컬 이미지 저장 구현

S01/S10/S13의 이미지 저장 경계: `NoteStorage.putImage(blob)`는 원본 바이트의 SHA-256으로 만든 `assets/<소문자 64자리 해시>.<확장자>`를 반환한다. `readImage(path)`는 해당 저장소에서만 읽고 경로·파일 형식·해시를 검증한 Blob을 반환한다. MIME 선언 대신 PNG/JPEG/GIF/WebP 파일 서명을 사용하며 SVG·알 수 없는 형식과 20 MiB 초과 입력은 거부한다. 원본 바이트를 변환하거나 업로드하지 않는다.

실제 폴더에서는 내부 `assets/` 디렉터리에 저장한다. 노트 목록은 기존처럼 폴더 최상위 Markdown만 읽는다. 같은 해시 쓰기는 직렬화하고 기존 파일은 검증 후 재사용한다. 기존 파일이 손상되거나 외부에서 바뀌었다면 덮어쓰지 않는다. 새 쓰기는 close와 다시 읽기 검증까지 끝나야 성공한다. 실패한 쓰기의 스트림은 가능하면 abort한다. 실패로 남은 빈 파일이나 참조되지 않는 이미지를 자동 삭제하거나 덮어쓰지 않는다.

데모는 노트 localStorage와 별개인 IndexedDB `granite.image-assets.v1`의 `images` 저장소를 사용한다. 키는 저장소 ID와 이미지 경로의 조합이며 트랜잭션 완료 이후에만 저장 성공을 반환한다. 읽기 실패·권한·용량·트랜잭션 오류는 호출자에게 전달한다. 본문은 이미지 저장 성공 후 편집기에서 별도로 변경한다.

## 저장 경계 검증

`tests/unit/assets.test.ts`는 실제 임시 디스크 바이트를 뒷받침한 테스트 핸들로 중복·동시 저장, 원본 바이트, 지원 형식과 MIME 위장, 크기 제한, 경로 이탈, 손상된 기존 파일 보호, 저장소 간 분리, 쓰기 각 단계 실패 시 노트 보존, close 완료 대기를 검증한다. 이 테스트는 네이티브 폴더 선택·권한 UI 검증이 아니다. 데모 IndexedDB와 실제 편집기 붙여넣기 여정은 별도 브라우저 검증 대상이다.

## 외부 쓰기와 원자성 한계

이미지가 없음을 확인한 뒤 생성 핸들을 얻더라도 다른 프로그램이 그 사이 파일을 만들었을 수 있다. 따라서 반환된 파일을 다시 읽고, 쓰기 스트림을 연 뒤와 close 직전에도 대상 경로가 여전히 빈 파일인지 확인한다. 예상하지 못한 바이트가 보이면 스트림을 중단하고 외부 파일을 보존한다. 최초 검사에서 이미 존재했던 빈 파일도 자동 덮어쓰지 않는다. 이 추가 검사는 생성·스트림 열기·쓰기 중 외부 바이트를 주입하는 결정적 디스크 회귀 테스트로 검증한다.

File System Access API는 조건부 생성이나 비교 후 원자적 commit(CAS)을 제공하지 않는다. 마지막 검사와 close 사이 외부 프로그램의 수정까지 원자적으로 차단한다고 보장하지 않는다. 브라우저 잠금은 협력하는 Granite 탭의 작업을 직렬화하며 외부 프로그램은 잠그지 않는다. 실패 후 남은 빈 파일은 다른 작성자의 파일인지 안전하게 증명할 수 없어 자동 삭제하지 않는다. 해당 경로가 남아 있으면 같은 이미지의 재시도도 거부될 수 있다.
