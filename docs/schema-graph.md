# 노트 속성과 연결

S17 구현. [수용 기준](superpowers/specs/2026-10-25-typed-notes-visual-review.md#s17-schemaorg-기반-노트-그래프).

노트 제목 아래 **속성**을 펼치면 유형과 YAML 원문을 확인하고 편집할 수 있다. 속성이 없는 노트는 그대로 일반 노트다. **속성 추가**를 선택할 때만 본문 맨 앞에 frontmatter를 만든다. Book, Person, Article, ScholarlyArticle, CreativeWork, Thing 선택지를 제공하며 다른 schema.org 이름도 YAML 원문에 쓸 수 있다.

```yaml
---
type: Book
author: "[[어슐러 르 귄]]"
about:
  - "[[글쓰기]]"
custom: 내 고유 속성
---
읽으며 남기는 생각.
```

`type: https://schema.org/Book`, 여러 타입 배열, 따옴표로 감싼 `"@type": Book`도 읽는다. 타입이 없는 노드는 내부 그래프에서 Thing으로 취급한다. `name`, `@id` 등 임의 속성이 노트 제목이나 파일명을 바꾸지 않는다. 타입과 속성의 유효성을 외부 서버에 조회하거나 노트를 전송하지 않는다.

연결 패널의 **노트 그래프**를 펼치면 현재 노트로 들어오는 관계와 나가는 관계를 탐색한다. `author`, `about` 등 속성 이름을 관계에 표시한다. 직접 문자열 또는 문자열 배열에 포함된 `[[제목]]`을 관계로 읽는다. 중첩 객체/배열은 보존하고 표시하지만 관계로 해석하지 않는다. 본문 링크는 별도 `본문 링크` 관계다. 같은 출발/도착/속성의 반복 링크는 한 번 표시한다. 없는 제목은 **없는 노트 · 만들기**로 표시하고 선택하면 기존 생성 확인 창을 연다. 독립된 노트도 파일명을 ID로 가진 그래프 노드다.

속성 변경도 본문과 같은 자동 저장·외부 변경 충돌·복구 초안 경로를 거친다. 미저장 변경도 그래프에 즉시 반영한다. YAML 전체를 재직렬화하지 않으므로 주석, 알 수 없는 속성, 기존 줄바꿈과 본문은 자동으로 바뀌지 않는다. 기존 `granite-title` 헤더가 있는 파일은 헤더 뒤의 Note.body에서 frontmatter를 읽는다. 기존 파일이나 데모 데이터를 자동으로 마이그레이션하지 않는다.

오류가 있는 YAML도 저장 가능한 텍스트다. 오류를 고칠 때까지 해당 속성에서 관계를 만들지 않는다. 32,768자를 넘는 속성, 과도한 깊이/노드 수, YAML 별칭과 사용자 태그를 제한한다. 속성은 안전한 Map과 React 텍스트로 표시하며 HTML로 실행하지 않는다. 닫는 `---`가 없다면 **원문 보기**에서 추가한다.

## 확인한 범위

- `tests/unit/schema-graph.test.ts`: S17 타입·다중 타입, 원문 및 주석 보존, 미지정 필드, 오류·별칭·사용자 태그·크기·깊이 제한, prototype 이름의 키, 노드 ID, 고립된 노트, 속성/본문 링크 분리, 없는 대상, 초안 변경, 중첩 관계 제외.
- `tests/e2e/schema-graph.spec.ts`: 데모에서 실제 속성 편집·자동 저장·재로드, 원문 보존, 관계 갱신, 없는 대상 생성, HTML 문자열 안전 표시, 390px 화면 가로 넘침 확인.
