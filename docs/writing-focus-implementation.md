# 글쓰기 집중 화면 구현·검증

2026-10-24. 기준: [간결한 글쓰기 화면과 맥락별 링크 편집](superpowers/specs/2026-10-24-writing-focus.md), [S01–S12](superpowers/specs/2026-10-23-granite-mvp-design.md). CMS 참고 소스와 확인 범위는 [참고 조사](writing-focus-reference.md)에 기록한다.

피드백은 시각 방향 변경과 링크 편집 조건의 명세 보완으로 분류했다. 기본 스펙 S04에 링크별 선택 범위와 클릭 동작을 명시하고, 이번 스펙의 7개 수용 기준에 맞춰 구현했다.

## 구현과 수용 기준

| 이번 기준           | 구현·검증 결과                                                                                                                                                                                                                                                                                                   | 기존 기준             |
| ------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------- |
| 1. 맥락 링크        | 위키·안전한 Markdown 링크의 구문을 숨기고 레이블을 편집 가능한 텍스트 장식으로 표시한다. 선택이 전체 구문과 교차하거나 양끝에 닿으면 해당 링크만 원문을 보인다. 같은 줄의 다른 링크는 유지한다. 양쪽 링크의 내부·경계·외부 위치와 범위 선택을 단위 테스트한다.                                                   | S04, S06              |
| 2. 편집과 이동      | 일반 클릭은 레이블 안에 커서를 놓고 원문을 드러낸다. Cmd/Ctrl+클릭은 내부 노트·HTTP(S) 출처를 연다. 미리보기 hover는 내용을 바꾸지 않는다. 하단 한 곳에 사용법을 표시한다. 브라우저에서 일반 클릭 후 입력, 외부 창, 내부 이동, 없는 노트 생성을 확인했다.                                                        | S04, S06, S08         |
| 3. 안전             | 여러 줄 링크는 원문으로 남는다. 인라인·블록 코드의 링크는 탐색 대상이 아니다. 조합 중에는 기존 장식 위치만 변경에 맞춰 옮기고 조합 종료 뒤 다시 계산한다. 이스케이프된 레이블의 역슬래시는 미리보기에서만 숨긴다. 원문·코드·위험한 URL, 한글 조합·취소·다시 실행, 붙여넣기·자동완성·HTML 비실행 회귀를 확인했다. | S04, S06–S08, S10     |
| 4. 간결한 시각 체계 | 흰색·회색 배경과 짙은 본문, 절제된 파란 회색 링크를 사용한다. 식물·종이 장식, 장식 카드, 홍보 문구, 명조 제목을 제거했다. 중첩된 과거 스타일을 정리하고 기존 CSS를 다시 구성했다. 새 의존성이나 서체 다운로드는 없다.                                                                                            | S12                   |
| 5. 가독성           | 실제 CodeMirror 본문 요소의 고딕체·17px·30.6px 행간을 브라우저에서 확인한다. 원문 보기는 고정폭이다. 제목은 28px이며 제목·본문·하단은 최대 700px를 공유한다. 390px 집중 화면의 실제 본문은 16px·28.8px 행간·354px 너비이며 가로 넘침이 없다.                                                                     | S12                   |
| 6. 집중 모드        | 버튼 이름·아이콘·aria 상태가 실제 표시와 일치한다. 집중 중 연결 패널 열기는 집중을 끝내고 탐색·연결 패널을 다시 표시한다. 데스크톱과 좁은 화면의 집중 모드를 확인했다.                                                                                                                                           | S09, S12              |
| 7. 기능 보존        | 시작 화면은 제목·설명·폴더 열기·데모 진입과 재연결/오류 안내를 유지한다. 재발견은 단순한 노트 항목이다. 데일리·덤프·검색·옮기기·백링크·복구 회귀가 통과했다. 저장소 코드는 변경하지 않았다.                                                                                                                      | S01–S03, S05, S09–S10 |

테스트: [편집기 단위 테스트](../tests/unit/editor.test.tsx), [브라우저 여정](../tests/e2e/journeys.spec.ts). 새 회귀는 `writing-focus` 이름으로 식별한다. 실제 본문 서체를 덮어쓰던 CodeMirror 기본 스타일과 좁은 창에서 집중 화면을 좁히던 CSS 우선순위 문제는 브라우저 실패를 재현한 뒤 수정했다. 이스케이프 레이블의 역슬래시 노출도 실패하는 단위 테스트를 먼저 추가해 수정했다.

마지막 화면 정리 뒤 기존 S08 제목 가져오기 여정이 30초 타임아웃을 재현했다. trace에서 텍스트박스의 빈 중앙을 클릭하는 동안 열린 붙여넣기 메뉴의 `.paste-actions`가 포인터를 가로막는 것을 확인했다. 테스트를 보이는 첫 원문 줄 클릭 → 문서 끝으로 이동 → 계속 입력 순서로 보정했다. 지연 응답이 변경된 텍스트를 덮어쓰지 않는 원래 검증과 30초 제한은 그대로 유지했다. 보정 뒤 해당 브라우저 테스트는 1개 통과(2.6초)했다. 제품 코드는 추가 변경하지 않았다. 통합 작업에서 단위 42개, 전체 브라우저·디스크 33개, 타입 검사와 빌드를 다시 실행했고 모두 통과했다.

빌드는 기존과 같은 큰 JavaScript 청크 안내를 출력했다(약 794 kB, gzip 267 kB). 검사 실패는 아니다. Chromium은 기존 Granite 4173 서버를 사용했으며 다른 개발 서버를 중단하지 않았다.

CSS 색상값의 WCAG 대비 계산에서 보조·저장·탐색 글자 `#595959`는 흰 배경 7.00:1, 선택된 노트의 `#e9e9e9` 배경 5.77:1이다. 본문·링크·오류 색도 사용된 배경에서 4.5:1을 넘는다. 이는 사용한 색상 조합의 계산이며 전체 접근성 인증은 아니다.

## 검증 한계

한글 조합 회귀는 Chromium DevTools Protocol의 `Input.imeSetComposition`과 `Input.insertText`로 조합 단계를 전달해 문서와 취소·다시 실행을 검증했다. macOS 실제 한글 입력기의 물리 키 입력·후보 선택을 검증한 것은 아니다.

폴더 선택창·네이티브 권한 승인/거부는 이번 작업에서 검증하지 않았다. 실제 디스크 어댑터 7개 테스트는 Node 파일 I/O 기반 handle 대역이며 Chrome 네이티브 picker나 권한 UI를 검증한 것으로 해석하지 않는다. 외부 링크 창은 테스트 응답으로 확인했으며 실제 사이트의 CORS나 운영체제 클립보드 검증은 아니다.

## 변경 파일

- `src/App.tsx`: 시작·발견 화면 단순화, 집중/연결 패널 상태·사용 안내.
- `src/editor/Editor.tsx`: 링크별 장식과 modifier 탐색, 조합 중 장식 안정화.
- `src/styles.css`: 무채색 시각 체계, 실제 편집기 서체·행간·너비, 좁은 화면.
- `tests/unit/editor.test.tsx`, `tests/e2e/journeys.spec.ts`: 범위·클릭·이스케이프·조합·화면 회귀.
- 기본 스펙 S04, 이 보고서, `writing-focus-*` 화면 이미지.

## 독립 검토와 직접 확인

독립 검토에서 발견한 이스케이프 레이블 표시 회귀를 수정한 후 재검토 승인을 받았다. 오케스트레이터도 Chrome DevTools에서 실제 본문 요소의 17px·30.6px·고딕체·700px 폭, 집중 모드의 연결 패널 열기 동작을 직접 확인하고 데스크톱·390px 집중 화면 캡처를 확인했다. 미해결 차단 사항은 없다. 네이티브 IME·권한창은 위 검증 한계에 포함한다.
