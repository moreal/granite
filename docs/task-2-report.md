# Task 2 QA 보고서

2026-10-23, Granite MVP 작업 트리 기준. QA는 운영 소스를 수정하지 않고 브라우저 수용 테스트, 실제 디스크 어댑터 표본, 리뷰 자료를 작성했다. 운영 수정은 문제를 전달받은 구현 담당자가 수행했다. 커밋과 원격 게시를 하지 않았다.

상태: 독립 검토의 복구 후보 전환/이전 초안 정리 수정을 포함해 최종 자동 검증을 완료했다.

## 최종 검증

| 명령                | 결과                                                           |
| ------------------- | -------------------------------------------------------------- |
| `npm test`          | 4개 파일 / 38개 테스트 통과, 종료 0                            |
| `npm run typecheck` | 앱 + Playwright 설정/E2E/helper 통과, 종료 0                   |
| `npm run build`     | 성공, 종료 0. JS 796.28 kB / gzip 268.02 kB, 큰 청크 안내 있음 |
| `npm run test:e2e`  | 26/26 통과, 22.2초. 재시도 0                                   |

환경: macOS arm64, Node.js 26.12.0, Chromium 156.0.8078.4 / revision 1248. 최종 E2E는 `npm run test:e2e` 그대로 실행했다. 초기 캐시 브라우저 실행 파일 우회는 최종 검증에 사용하지 않았다.

26개는 사용자 UI 10개, 옮기기 실패 2개, 제목 요청 취소 2개, 초안 복구 5개, 디스크 어댑터 7개로 구성된다. 각 브라우저 테스트는 새 컨텍스트를 쓰며 두 탭 회귀만 의도적으로 같은 저장소를 공유한다. URL 응답은 네트워크 대역으로 제어하고, 붙여넣기는 실제 CodeMirror에 ClipboardEvent를 전달한다.

## 발견 및 수정 확인

| 문제                                                                                           | QA 증거와 최종 결과                                                                                                                    |
| ---------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| 제목 가져오기 중 Escape/닫기로 취소해도 늦은 응답이 URL을 바꿈                                 | 양쪽 모두 `[취소 뒤 온 제목](url)`로 바뀌는 실패를 재현. `fetch-cancel.spec.ts` 2개가 수정 후 통과                                     |
| 선택 텍스트에 URL을 붙이면 Markdown 기본 핸들러가 먼저 별칭으로 바꾸어 선택 메뉴가 생기지 않음 | 메뉴 버튼 대기 실패와 자동 생성된 Markdown 확인. `journeys.spec.ts`에서 메뉴 표시와 선택 별칭 적용이 수정 후 통과                      |
| 다른 탭의 저장이 저장 실패한 탭의 초안을 지움                                                  | A 실패 → B 저장 → A 충돌 → A 새로고침에서 B 본문만 남는 실패 재현. `recovery.spec.ts` 두 탭 사례가 수정 후 A 초안과 B 저장을 모두 보존 |
| 여러 줄 Markdown 링크의 라이브 프리뷰 오류 위험                                                | 독립 검토자 보고에 따라 회귀 추가. 커서 이동·입력·저장 및 console/pageerror 없음이 통과. 수정 전 QA 재현을 수행했다고 주장하지 않음    |

첫 실행에서는 빈 본문 helper의 빈 insertText, 자동완성 선택 위치, 검색 결과의 본문 일치까지 잡는 locator도 수정했다. 이는 테스트 결함이며 운영 제품 문제로 분류하지 않았다. E2E 타입 검사에 필요한 `@types/node`와 스크립트 변경은 구현 담당자가 추가했으며 QA는 `tsconfig.e2e.json`과 handle 반환 타입을 보완했다.

2차 검토는 복구 후보를 바꾸면 방금 편집한 고유 문장이 사라질 수 있는 문제와, 복구한 A를 A2로 저장해도 이전 A가 다시 복구되는 문제를 보고했다. `recovery.spec.ts`에 각각 실제 UI 회귀를 추가했고, 수정 후 후보 전환을 거쳐 고유 문장을 다시 선택할 수 있음과 A2 저장/새로고침 뒤 이전 A가 충돌로 되살아나지 않음을 확인했다. 이 두 항목의 수정 전 QA 브라우저 실행은 하지 않았다.

## 실제 파일의 검증 수준

운영 `DirectoryStorage`를 실제 임시 디렉터리에 연결한 Node 기반 handle 대역으로 검사했다. 최상위 `.md`만 목록에 나타남, 일반 파일 본문 보존, 인코딩·긴 제목 왕복, 중복 거부, 외부 변경 거부, createWritable/write/close 실패 시 기존 바이트 유지, close 전 완료하지 않음을 확인했다. 표본은 각 테스트 후 제거한다.

이 결과는 실제 디스크 I/O 증거이며 Chrome의 실제 FileSystemDirectoryHandle·OS 선택창·권한 승인 증거는 아니다. 실제 폴더 선택/취소/권한 거부/철회/재연결, 동일 이름 실제 폴더 간 초안 분리, 실제 한글 IME, 운영체제 클립보드, 실제 외부 사이트 CORS는 수동 미검증이다. [수용 검증표](acceptance-matrix.md)의 네이티브 확인표로 후속 확인한다.
