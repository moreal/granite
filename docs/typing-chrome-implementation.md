# 입력 중 주변 UI 흐림 구현·검증

2026-10-24. [글쓰기 명세의 추가 요구](superpowers/specs/2026-10-24-writing-focus.md#추가-요구-입력-중-주변-ui-흐림)를 구현했다. S04 편집, S08 붙여넣기, S09 집중, S10 저장·복구, S12 접근성에 연결된다.

## 동작과 변경 파일

- `src/editor/Editor.tsx`: CodeMirror의 사용자 입력·삭제·조합·undo/redo 트랜잭션을 구분해 알린다. URL 붙여넣기의 사용자 트랜잭션을 명시한다. 외부 value 동기화는 입력으로 취급하지 않는다. 붙여넣기 대화상자의 열림 상태도 알린다.
- `src/App.tsx`: 본문 사용자 편집으로 흐림 상태에 진입한다. 포인터 이동·누름·터치, Tab/Escape, 저장/검색 명령, 편집기 밖 포커스와 버튼 명령으로 복원한다. 선택·대화상자가 열려 있으면 선명하며 노트·저장소·집중 모드 변경 시 초기화한다. 저장 상태 갱신은 흐림을 다시 켜지 않는다.
- `src/styles.css`: 탐색·상단 도구·연결·날짜/단어 수·하단 작업/안내만 opacity 0.3, 250ms ease-out. 복원은 transition 없음. reduced-motion도 transition 없음. 제목·본문·저장·오류·복구·메뉴의 조상에는 opacity를 적용하지 않는다. 기존 수동 집중 모드의 숨김 규칙은 유지한다.
- `tests/unit/editor.test.tsx`, `tests/e2e/typing-chrome.spec.ts`: 아래 자동 회귀와 스크린샷 증거를 추가했다.

의존성, 저장 구현, 노트 바이트 형식은 변경하지 않았다.

## RED → GREEN

구현 전 사용자 편집 단위 테스트는 기대 6회에 실제 0회로 실패했다. 최초 브라우저 2개 테스트도 기대 opacity 0.3에 실제 1로 실패했다. 구현 후 해당 단위 9개와 최초 브라우저 2개가 통과했다.

확장 검증에서 undo가 원래 전체 선택을 복구하는 상황은 명세대로 UI를 선명하게 유지했다. 테스트의 잘못된 기대를 수정하고, 선택이 없는 빈 새 노트에서 undo/redo로 흐려지는 별도 경로를 검증했다. 제품 동작을 테스트에 맞춰 약화하지 않았다.

## 검증 결과

- `npm test`: 4개 파일, 44개 통과 (자동완성 명령 수정 후).
- `npm run typecheck`: 성공, 종료 코드 0.
- `npm run build`: 성공, 종료 코드 0. 기존 약 795kB JS 청크 크기 안내는 남아 있다.
- `npm run test:e2e`: 최종 41개 통과, 32.5초, 종료 코드 0 (브라우저 34개 + 실제 디스크 어댑터 7개).

새 브라우저 검증은 실제 계산 스타일과 조상 opacity의 곱을 검사한다. 주변 6개 영역의 0.3, 본문·제목·저장 상태·자동완성·붙여넣기 메뉴·대화상자·오류·복구 안내/조작의 유효 opacity 1을 확인한다. 정상 진입은 0.25s ease-out, 복원 및 reduced-motion은 0s를 검사한다. 일반 방향키, Tab/Escape, 검색/저장 명령, 선택, undo/redo, 노트 전환, 수동 집중 모드, Chromium CDP 한글 조합을 포함한다.

## 검증 한계

브라우저 검증은 별도 데모 저장소를 사용한다. 오류는 브라우저 저장 실패를 주입해 검증했다. 실제 폴더 선택창·권한 UI를 검증한 결과가 아니다. 기존 실제 디스크 어댑터 테스트도 브라우저 권한창을 대체하지 않는다. 한글 조합은 Chromium CDP 입력 경로이며 macOS 네이티브 IME나 운영체제 클립보드 검증은 아니다. reduced-motion은 브라우저 에뮬레이션으로 확인했다.

상위 담당자가 Chrome DevTools에서 주변 UI 유효 opacity 0.3, 본문·제목·저장·안내 1, Tab/마우스 이동 뒤 1/전환 0s, reduced-motion에서 전환 0s를 직접 확인했다. 수정본을 새로 로드한 뒤 오늘 명령 실행은 1/0s로 복원되고, 이후 일반 본문 입력은 다시 0.3이 되는 것도 확인했다. 독립 재검토에서 자동완성 수정이 승인됐으며 추가 발견 사항은 없었다.

## 독립 검토 후 자동완성 명령 복원 수정

독립 검토에서 P2 누락을 발견했다. CodeMirror의 `isUserEvent("input")`가 `input.complete`도 포함해, 자동완성의 마우스 선택 직후 다시 흐려졌고 Enter 선택은 선명하게 복원되지 않았다. 별도 실제 DevTools에서도 `@오늘` + Enter가 `[[2026-10-24]]`를 삽입한 뒤 sidebar opacity 0.3을 유지하는 현상이 재현되었다.

S06/S07/S12 회귀 테스트를 먼저 추가했다. 기존 노트 마우스 선택·Enter 선택, 오늘 명령 Enter, 새 위키링크 Enter의 4개 브라우저 테스트가 모두 실패했고, 완료를 명령으로 분류하는 단위 테스트도 기대 호출 1회에 실제 0회로 실패했다(RED).

`Editor`는 이제 `input.complete`를 명시적 명령 콜백으로 전달하고 일반 입력 알림에서 제외한다. 사용자 정의 날짜 명령에도 같은 완료 annotation을 붙였다. `App`은 명령 콜백으로 즉시 복원한다. 기존 저장·선택·메뉴 처리와 CSS는 변경하지 않았다. 수정 후 편집기 단위 10개와 새 완료 회귀 4개가 통과했다(GREEN). 각 브라우저 테스트는 완료 뒤 opacity 1/transition 0s뿐 아니라, 다음 일반 본문 입력에서 0.3으로 다시 진입함을 확인한다.

수정 후 전체 단위 44개, 타입 검사, 빌드, 포맷 검사와 diff 공백 검사가 통과했다. 첫 전체 E2E 재실행에서는 새 회귀 모두를 포함해 40/41개가 통과했고 기존 S06 키보드 자동완성 테스트가 한 번 실패했다. 메뉴가 보인 직후 ArrowDown/ArrowUp/Enter를 보내는 테스트이며 CodeMirror 기본 75ms interactionDelay와의 타이밍 경합으로 추정한다. 해당 테스트를 변경하지 않고 집중 5회 반복한 결과 5/5 통과했다. 확정 원인으로 단정하지 않는다.

최종 전체 재실행은 **41/41개 통과, 32.5초, 종료 코드 0**으로 마쳤다. 실패했던 기존 S06 테스트도 통과했다. 추가 자동완성 회귀 4개와 기존 reduced-motion·선택·복구·조합 검증 모두 포함한다.

통합 담당자의 최종 독립 실행에서도 단위 44개, 타입 검사, 빌드, 브라우저·디스크 41개(32.6초)가 모두 통과했다. 기존 S06 키보드 테스트도 통과했다.
