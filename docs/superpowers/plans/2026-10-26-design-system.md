# S27 디자인 체계 구현 계획

기준: [S27](../specs/2026-10-26-design-system.md), S01/S04/S10/S12/S19/S22/S24–S26. 현재 main에서 구현하고 독립 리뷰와 검증 뒤 통합한다.

1. 운영 컨트롤·전역 CSS·테마·민감한 native 입력 경계를 조사하고 현재 앱/Storybook을 작은 화면으로 기록한다. 기존 팔레트/40·44·32px와24px 인라인 리듬을 보존한다.
2. 네이티브 반응성/ref/이벤트/기본 button·명시적 submit 회귀를 먼저 작성한다. 의미 토큰·중립 reset·Button·직접 필드/메뉴/안내 규칙을 만든다. UI/본문/코드 역할과 기존 테마 해석기를 연결한다.
3. App·설정/대화상자·속성·사이드바·그래프·툴바·복구·붙여넣기를 실제 계약으로 옮긴다. 모든 운영 button이 명시적인 뒤 전역 크기/정렬/hover를 제거한다. 중복 최종 CSS 선언을 합치고 기능 배치만 기능 스타일에 둔다.
4. Design System 기초/상태/상호작용 story와 수정 안내를 추가한다. 실제 속성/설정/앱 툴바에 토큰을 덮어써 전파와 inline/list 격리, 초점/disabled/ref/제출과 테마의 비저장을 검사한다.
5. 집중 회귀 뒤 전체 단위·타입·Pages 앱 빌드 → Storybook 빌드·전체 앱/컴포넌트/시각 검사를 실행한다. source 제공물의 새 CSS/TSX 포함을 확인한다. 실제 작은 앱/운영 Storybook 확대 화면을 열어 확인하고 독립 코드·화면 리뷰 결과를 반영한다.

구현 기록과 실행 로그는 `.superpowers/design-system/implementation.md`에 남긴다. picker/권한·OS IME는 합성 입력 결과로 주장하지 않는다.
