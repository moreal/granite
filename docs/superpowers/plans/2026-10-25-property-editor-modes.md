# S24 구현과 검증 계획

[합의된 기준](../specs/2026-10-25-property-editor-modes.md)에 따라 기본 폼과 선택 가능한 YAML 편집기를 제공한다.

1. 기존 YAML 제한과 AST 소유권 검증을 공유해 scalar 위치/정확한 교체를 계획한다. 오프라인 유형 상속·범위 판정과 로컬 노트 인덱스를 UI에서 분리한다.
2. 설정을 저장하고 미확정 폼 초안이 있을 때 전환을 보류한다. 전체 원문에서는 속성 편집 UI를 숨기며 복잡한 값은 원문으로 연결한다.
3. 같은 완성/범위 안내를 폼·YAML·전체 원문에 연결한다. 기존 workspace 자동 저장 및 충돌 흐름을 사용한다.
4. label과40px 값 컨트롤의 실제 정렬을 수정하고 운영 Storybook 예제와 키보드 회귀를 추가한다.
5. 독립 리뷰 전 소스를 동결한다. 단위/타입/앱 빌드 → Storybook 빌드 → 전체 앱 브라우저 → 컴포넌트 → 시각 검사를 순서대로 실행한다. 좁은 화면과 데스크톱의 라이트/다크 캡처를 직접 열고 결과/제한을 verification에 남긴다. 리뷰·검증 후 루트 담당자가 main에 커밋/푸시한다.
