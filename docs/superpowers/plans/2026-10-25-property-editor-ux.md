# S25 속성 입력 UX 구현 계획

기준: [S25 승인 기준](../specs/2026-10-25-property-editor-ux.md), S21/S24, `.superpowers/property-ux/brief.md` 및 두 실제 UX 평가. main 직접 작업은 사용자 승인 사항이다. 루트가 독립 리뷰·최종 통합·커밋·push를 맡는다.

1. **입력/초안 회귀를 먼저 추가:** 실제 NoteProperties/YamlEditor/PropertyValueInput에 경고 시점, 접힘, 잘못된 폼, 숫자 초안 전환, 포커스, 결과 없음 검사를 추가하고 실패를 확인한다.
2. **최소 운영 수정:** 안전하게 읽은 맵을 분류하고 폼 복구를 안내한다. 현재 초안을 보호하고 명시적 적용/취소 뒤 안전한 초점을 돌린다. YAML 편집/검증 상태를 원문 저장과 분리하고 전체 원문에도 명시적 편집/떠남/저장 신호를 연결한다. 기존 커서 가드를 보존한다. 이름/유형 후보는 목록만 스크롤한다.
3. **실제 화면 회귀:** 실제 운영 Storybook의 준비 완료 후 native 키보드로 입력·조합·대기·흐림·저장·접힘·검색/초안 보존/포커스/후보 가시성을 검사한다. 실제 앱의 자동 저장·재열기·원문/방식 전환도 확인한다. 작고 결정적인 운영 상태를 이야기로 추가하고 라이트/다크 좁은/데스크톱 화면을 검토한다.
4. **검증과 독립 평가:** 전체 단위/타입/앱·Storybook 빌드, 관련 앱 브라우저와 전체 컴포넌트 검사를 실행한다. 소스를 동결해 독립 코드 리뷰와 두 UX 평가자에게 최종 화면을 재평가하도록 전달한다. 원인 있는 실패만 수정하고 근거·한계를 문서화한다.

검토 초점: raw invalid YAML 자동 저장, 기존 caret/undo, 후보 클릭의 blur 오해, 문서/설정 변경 시 초안 안전성, 잘못된 폼에서 기존 초안 보존, 경고와 저장 오류의 분리, 접힌 상태 발견성. 새로운 서비스·저장 경로·의존성·편집기 교체·시각 구조 개편은 범위 밖이다.
