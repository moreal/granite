# S26 읽는 속성에서 노트 열기

2026-10-25 도그푸딩의 `author: '[[작가]]'` 값이 편집 버튼으로만 보이는 피드백은 **명세 보완**이다. 본문 편집 중의 Cmd/Ctrl+클릭 규칙과 별도로, 폼에서 읽는 속성은 링크를 바로 열 수 있어야 한다.

- **S26a 명확한 이동과 편집:** 폼의 문자열 또는 직접 목록 문자열에 있는 일반 `[[제목]]`는 구분되는 링크 모양의 키보드 접근 가능한 노트 열기 조작으로 표시한다. 일반 클릭과 Enter로 기존 노트를 열며 같은 값의 편집/원문 편집 조작은 별도로 제공한다. 조작 안에 다른 조작을 중첩하지 않는다. 여러 링크와 주변 텍스트, 숫자·불리언·null 목록 값은 그대로 읽을 수 있다. 적용/취소 후 기존 속성 편집 버튼으로 초점을 돌리는 S25e를 유지한다.
- **S26b 동일한 연결과 안전:** 기존 위키링크 파서의 대괄호·역슬래시 이스케이프와 코드 제외를 사용한다. 대상은 기존 앱의 노트 열기 경로에 전달하고 없는 대상은 기존 생성 확인으로 안내한다. 자동으로 노트를 만들지 않는다. HTML이나 URL처럼 보이는 제목도 텍스트와 로컬 노트 제목으로만 다루며 HTML 실행·외부 URL 이동을 도입하지 않는다. type/@type 유형 선언과 복잡한 맵은 기존 텍스트 표시를 유지한다. 저장된 Markdown과 그래프 연결을 변경하지 않는다.
- **S26c 이동 전 초안 보존:** 어떤 속성이든 미확정 폼 초안이 있으면 속성 링크 이동을 보류한다. 기존 S25d 적용/취소 안내를 보여 주고 초안 입력으로 초점을 돌린다. 값·검증 오류를 보존하며 몰래 적용하거나 폐기하지 않는다. 적용/취소 후 다시 누르면 이동한다.
- **S26d 운영 화면 검증:** 실제 앱의 클릭·Enter·저장/재열기·연결, 여러/이스케이프 링크·없는 대상·안전한 HTML 표시·잘못된 숫자 초안 보존을 브라우저로 확인한다. Storybook의 운영 컴포넌트에서도 실제 대상 표시와 돌아오기, 편집 중 이동 보류를 재현한다. 좁은 화면과 데스크톱의 라이트·다크를 작은 캡처로 직접 확인한다. YAML/전체 원문은 기존 텍스트 편집 방식을 유지한다.
