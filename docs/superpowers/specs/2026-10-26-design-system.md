# S27 바꾸기 쉬운 디자인 체계

2026-10-26 사용자의 “실제 디자인 시스템으로 이후 디자인을 쉽게 바꾸기” 요청은 **명세 보완 / 구조 확장**이다. 현재의 차분한 한국어 글쓰기 화면과 S01–S26 동작을 보존한다. 새 시각 방향이나 UI 프레임워크 도입이 아니다.

- **S27a 기본값:** 의미별 밝은/어두운 색, UI/본문/코드 서체, 글자 크기, 간격, 곡률, 테두리·초점, 컨트롤 높이, 레이어와 기존 모션은 `src/design-system/tokens.css`를 기준으로 한다. 기존 테마 설정/시스템 해석기를 유지한다. CodeMirror/풍부한 본문용 기존 이름은 이 기준을 참조하는 호환 별칭이다. 본문 17px/1.8, 좁은 창 16px, 700px 읽기 폭, 기본 작업40px·편안한 작업44px·최근 행32px·인라인24px 리듬을 유지한다. 어두운 주요 버튼의 hover/disabled 상태도 읽을 수 있는 전경/배경 쌍을 쓴다.
- **S27b 운영 재사용:** 운영 앱의 작업·아이콘·목록·인라인 버튼은 실제 네이티브 Solid2 Button 계약을 쓴다. 주요/보조/조용한/위험 작업과 크기를 명시한다. 기본 `type=button`, 명시적 제출만 submit이다. 네이티브 disabled/ref/ARIA/이벤트와 반응성을 전달한다. 필드·배지·안내·후보 목록은 실제 운영 노드에 적용하는 공통 표현 규칙을 쓴다. 전역 button은 작업의 크기/정렬/hover를 강제하지 않는다.
- **S27c 동작 소유권:** YAML/원문은 기존 DOM·같은 값 재대입 방지·선택·undo·조합 처리를 유지한다. 메뉴 상태/키보드/스크롤, 클릭 중 초점 유지, 파싱·저장·초안은 기존 기능의 책임이다. 명세만으로 새 범용 입력 래퍼나 새로운 상태 관리기를 도입하지 않는다. 실제 좁은 앱 컨테이너의 속성 행 배치와 열린 목록의 한 번 클릭 적용/취소를 유지한다.
- **S27d 검토 장소:** Storybook의 Design System에 기본 색·글자·간격과 운영 버튼/필드/목록/인라인/후보/안내를 제공한다. 밝게/어둡게, 좁은320px, 긴 한글, 선택·초점·오류·disabled와 모션 축소를 검토할 수 있다. 기존 Production story는 유지한다. 미리보기 테마는 사용자 앱 설정을 저장하지 않는다.
- **S27e 변경 안내:** `docs/design-system.md`에 각 수정 위치, 변형 선택, 구성과 네이티브 동작 경계, story/회귀 추가법과 남은 기능별 스타일을 설명한다. 실제 속성·설정·툴바의 토큰 변경 전파와 inline/list 변형 격리를 회귀로 검사한다.

데이터/스키마/저장 방식, 새 서체·라이브러리, 편집기·완성 상태기 교체, 외부 토큰 게시·Figma 동기화는 범위 밖이다. 네이티브 폴더 선택/권한·OS IME·스크린리더 검증은 데모/합성 Chromium 검증과 구분한다.
