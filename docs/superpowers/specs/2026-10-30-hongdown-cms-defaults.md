# 블로그 CMS와 같은 hongdown 기본값 (S31)

분류: S20의 보수적인 정리 옵션을 블로그 CMS와 맞추는 사용자 요청에 따른 방향 변경. S30의 글쓰기 화면과 기존 데이터 보호 계약을 유지한다.

블로그 `.hongdown.toml`은 파일 포함/제외만 지정하고 CMS는 `hongdown -w`를 실행한다. 블로그 mise 설정은 CLI0.3.2를 지정하고 현재 PATH의 CLI와 Granite WASM은0.5.3이다. CMS 실행 파일 선택은 환경에 따르므로0.3.2/0.5.3 CLI와0.5.3 WASM의 합성 fixture 출력 일치를 각각 확인했다. Granite도 스타일 재정의 없이 같은 버전의 기본값을 사용한다. 기본값은 80열 재줄바꿈, H1/H2 밑줄 제목, 물결표 네 개와 정보 앞 공백을 쓰는 fence, 곡선 인용부호·말줄임표·em dash 변환이다. 수식 보존은 기본 활성화다.

- **S31a:** 실제 WASM의 기본 출력과 Granite 출력이 같아야 한다. 한글/영문 긴 문단, 제목, 인용부호, 말줄임표, dash, reference 링크와 코드 fence를 포함한다.
- **S31b:** 기본 활성화된 idle 자동 정리와 Cmd/Ctrl+S는 같은 결과를 원문에 적용하고 저장·새로고침 후 유지한다. 한 번의 undo로 정리 직전 원문으로 돌아가고 idle이 다시 정리하지 않는다. redo도 가능하다.
- **S31c:** 기본 fence spelling으로 바뀐 Mermaid는 같은 다이어그램으로 인식·표시한다. 일반 코드 내용/언어, 수식, 위키 대상, 이미지와 frontmatter의 보호를 유지한다. 목차는 fence 안 제목을 제외한다.
- **S31d:** 기존 selection/조합/동시 수정 취소와 충돌·복구 보호를 유지한다. 기본 정리가 위키 대상·자산·수식·다이어그램 의미를 바꾸면 원문 저장과 기존 실패 안내를 유지한다. 사용자 데이터를 기본값에 맞추기 위해 강제로 변환하지 않는다.

실제 사용자 폴더·picker·권한 UI·OS IME는 합성 데모 브라우저 검증과 구분한다.
