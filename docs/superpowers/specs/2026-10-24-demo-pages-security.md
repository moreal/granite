# 편집 예제와 공개 데모 배포

## S15 직접 편집하는 예제

이미지·인라인/블록 수식·언어가 지정된 코드·Mermaid를 한 노트에서 직접 고친다. 한국어의 짧은 안내와 실제 예제를 제공한다. 이미지 원본은 저장소에 함께 포함하고 기존 CAS 저장 API를 사용하며 외부 이미지 서비스에 요청하지 않는다. 새 데모와 기존 데모에 한 번 추가하되 사용자가 고친 노트·기존 제목·최근 열었던 노트를 덮어쓰지 않는다. 실패 후 다시 열기와 동시 열기에도 중복·데이터 손실이 없어야 한다.

## S16 배포와 워크플로 검사

GitHub Pages의 `/granite/` 경로를 사용하는 프로덕션 빌드를 검증한다. JS/CSS, KaTeX 폰트, Mermaid 지연 로딩, 예제 이미지가 서브경로에서 동작해야 한다. 공개되는 것은 앱과 포함된 샘플이며 사용자의 로컬 노트와 첨부는 업로드하지 않는다.

PR에서는 테스트·Pages용 빌드와 zizmor를 실행한다. Pages 배포는 main의 push 또는 main을 대상으로 한 수동 실행에서만 수행한다. 배포 권한은 배포 작업에만 부여하고 PR에 쓰기 권한을 주지 않는다. 공식 액션은 검증한 커밋으로 고정한다. zizmor 경고를 일괄 억제하지 않고 원인을 수정하며 불가피한 예외는 위치와 근거를 좁게 남긴다.

검증은 단위/브라우저 회귀, 배포용 빌드의 실제 정적 서버·서브경로, actionlint/zizmor, 실제 PR 체크로 나눈다. main에 머지되기 전에는 공개 배포가 성공했다고 주장하지 않는다. PR 머지는 별도 사용자 요청을 따른다.
