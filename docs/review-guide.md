## 10분 데모 투어

1. 시작 화면에서 **데모 둘러보기**를 연다. 샘플 노트와 **데모 · 별도 저장소** 표시를 확인한다. 데모의 글은 브라우저 저장소에 남는다.
2. **덤프**를 열고 `오늘 읽은 글에서 오래 남길 문장`을 적는다. 저장 완료를 확인하고 다른 노트로 갔다가 돌아온다. 문장이 남아 있어야 한다.
3. 그 문장만 선택하고 **새 노트로 옮기기**를 실행한다. 제목을 `오래 남길 생각`으로 정한다. 새 노트에 선택한 문장이 있고, 덤프의 원래 자리에 `[[오래 남길 생각]]` 링크가 있어야 한다.
4. 새 노트의 **백링크**에서 덤프 문맥을 보고 눌러 돌아간다. 검색에 제목 일부와 본문 단어를 각각 넣어 두 방식으로 찾는다.
5. 편집기에서 `[[`를 입력하고 기존 노트를 방향키와 Enter로 고른다. 이번에는 없는 제목 `다음에 읽을 것`을 넣고 링크를 열어 새 노트를 만든다. Escape로 메뉴를 닫는 것도 확인한다.
6. `@`에서 오늘·어제·내일을 넣고 원문 보기를 연다. 날짜가 `[[YYYY-MM-DD]]`로 남아야 한다. `hello@example.com`을 적을 때 메뉴가 불쑥 열리지 않아야 한다.
7. `https://example.com`을 붙여넣고 그대로 두기와 별칭 달기를 각각 써 본다. 문장을 선택한 상태에서 붙이면 그 문장이 별칭이 된다. Escape와 계속 입력으로 메뉴를 닫아도 URL이 사라지면 안 된다.
8. 제목 가져오기를 눌러 진행/성공 또는 실패 안내를 본다. 일반 사이트는 CORS 때문에 실패할 수 있다. 이 경우 URL이 남고 수동 별칭을 쓸 수 있어야 한다. 응답을 기다리는 동안 입력한 글이 뒤늦게 사라지면 문제다.
9. 강조·인라인 코드·Markdown 링크를 써서 읽기 표시와 원문 보기를 오간다. 한글을 천천히 조합해 입력해 보고 메뉴가 조합을 가로채는지 살핀다.
10. **다시 발견**에서 다른 노트를 연다. 패널을 접고 써 본 뒤 창을 좁힌다. 키보드 Tab만으로 주요 버튼에 닿고 저장 상태·작성 영역이 가려지지 않는지 확인한다. 새로고침 후 저장한 내용도 다시 연다.

## 실제 폴더로 확인하기

1. Finder에 비어 있는 `Granite 리뷰` 폴더를 만들고 간단한 `기존.md`를 넣는다. 중요한 개인 폴더 대신 이 폴더를 사용한다.
2. 앱의 **내 폴더 열기**를 누른 뒤 Chrome 선택창에서 폴더를 고르고 읽기/쓰기 권한을 승인한다. 취소하거나 거부해도 다시 선택할 수 있어야 한다.
3. `한글 / 질문?: 100% 🪨`라는 제목으로 노트를 만들고 고유 문장을 적는다. 저장 완료 후 Finder에서 파일을 연다. 폴더 최상위에 인코딩된 이름의 `.md` 하나가 있고 본문이 일치해야 한다. 제목은 앱에서 원래 문자 그대로 보여야 한다.
4. 같은 제목을 다시 만들려고 한다. 기존 노트가 유지되고 중복 안내가 나오는지 확인한다. 아주 긴 제목도 만들어 다시 열어 본다.
5. 앱에서 연 노트를 외부 편집기로 바꾸고, 앱에서도 고친다. 외부 변경을 조용히 덮어쓰면 문제다. 충돌 안내와 작성 중 초안이 남고 복사/다운로드로 꺼낼 수 있어야 한다. 디스크 내용을 다시 읽는 동작이 있다면 초안을 버리기 전 확인이 필요하다.
6. 브라우저를 새로고침하고 같은 폴더를 다시 선택한다. 실패했던 초안이 복구 가능한지 확인한다. 상세한 권한 철회·다른 폴더 분리 확인은 [네이티브 확인표](acceptance-matrix.md#네이티브-chrome-수동-확인표)를 따른다.

폴더 선택창·권한창은 일반 Playwright 파일 업로드와 다르다. 자동 테스트 통과만으로 실제 Chrome 승인 흐름이 검증됐다고 보지 않는다. 확인한 환경과 직접 수행한 항목을 리뷰에 남긴다.

## 기대하는 경계

- 실제 폴더의 최상위 Markdown만 다룬다. 하위 폴더 탐색과 최초 생성 후 제목 변경·삭제는 MVP 범위 밖이다.
- 노트 본문은 서버에 보내지 않는다. URL의 제목 가져오기는 선택한 URL에 직접 요청하며, CORS가 허용되지 않으면 실패한다. 인증이나 우회 프록시는 사용하지 않는다.
- 새 노트로 옮기기는 두 파일을 순서대로 저장한다. 대상만 저장되고 원본 저장이 실패하면 사본이 생겼다는 안내와 원문이 남아야 한다.
- 데모 저장과 실제 파일 저장은 분리된다. 저장 완료 표시는 해당 저장소가 성공을 확인한 뒤 나와야 한다.

## 의견 남기기

[도그푸딩 양식](../.github/ISSUE_TEMPLATE/dogfooding.yml)에 **한 가지 경험**을 적는다. 관련 S 번호, 데모/실제 폴더, 하려던 일, 최소 재현 순서, 기대와 실제 결과를 남기면 다음 수정이 명확해진다. 데이터가 사라졌다면 직전 저장 표시·새로고침 여부·외부 편집 여부를 함께 적고, 공개해도 되는 문장으로 재현한다.

분류는 **스펙 위반**(약속된 동작이 안 됨), **스펙 부족**(판단 기준이 빠짐), **방향 변경**(다른 경험을 원함) 중 하나다. 스펙 부족과 방향 변경은 스펙을 먼저 고친다.
